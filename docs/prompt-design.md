# Jev への問い方の設計メモ

実験 01 で踏んだ失敗と、その直し方の記録。

## 失敗 1: 「重要度」で尋ねると除外指示が壊れる

### 症状

「鉄道を非表示にして」と指示すると、**鉄道が「通常」扱いで残った**。
消えてほしい要素が消えない。

### 原因

`score` の criteria を「どれだけ重要か」という一次元の尺度で書いていた。

```
0. 発話が求める表示とは無関係。非表示にしてよい。
…
4. 発話が名指しした主役。最も強調すべき。
```

この軸は **「言及されている」と「表示すべき」を区別できない**。
「鉄道を非表示にして」の鉄道は、発話に最も関連が深い要素である。
だからモデルは低く振り切れず、中間値に落ちる。
尺度そのものが除外指示を表現できていなかった。

一次元の順序尺度は、両端が**同じ語彙で語られる**ときに破綻する。
「関連が深い」は強調の理由にも削除の理由にもなるためである。

### 直し方

軸を「要素の属性（どれだけ重要か）」から
**「取るべき行動（どう扱うか）」**へ振り直した。

```
0. 発話はこの要素を地図から取り除くよう求めている。または発話の目的にとって全く不要。地図から消す。
1. 発話が求めるものではない。邪魔にならないよう薄くする。
2. 発話は言及していないが、場所を見失わないために通常どおり残す。
3. 発話が求める内容に直接関わる。はっきり見せる。
4. 発話が名指しして見せるよう求めた主役。最も強調する。
```

要点は 3 つ。

1. **レベル 0 に「取り除くよう求めている」を明示する。**
   除外指示と「無関係な要素」の両方が最下段に落ちる受け皿を作る。
2. **質問文を行動で書く。**
   「どれだけ重要か」→「この発話を実行したとき、どう扱うべきか」。
3. **誤読しやすい推論を state で先回りして否定する。**
   「指示に含まれる言葉と関連が深いことは、その要素を見せるべき理由にはなりません。」

### 一般化

`score` プリミティブの criteria は、**測りたい属性ではなく、
結果として取ってほしい行動**で書く。
判断がそのままシステムの動作に結びつくとき、この差は致命的になる。

## 検証したい発話

この種の破綻は、指示の向きが反転する発話で出る。
判定を変えたら以下を必ず通すこと。

| 発話 | 期待 |
| --- | --- |
| 鉄道を非表示にして | 鉄道 = 非表示 |
| 建物を消して道路だけにして | 建築物 = 非表示 / 一般道路 = 強調 |
| 等高線がうるさいので消して | 等高線 = 非表示 |
| 鉄道以外は全部いらない | 鉄道 = 強調 / 他の大半 = 非表示 |
| 文字を全部消して | 注記 = 非表示 |
| 人工物を消して自然だけにして | 建築物・道路・鉄道 = 非表示 / 水域・地形 = 強調 |

肯定形（「鉄道を強調して」）だけで試すとこの欠陥は見つからない。
**否定形・除外形を必ず混ぜる。**
